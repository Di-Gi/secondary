# Secondary Mind Project Documentation

This directory contains all project documentation, analysis, and development guidelines for Secondary Mind.

## Directory Structure

### Root Level (Important Files)
- `development-rules.md` - Core development guidelines and principles
- `task-template.md` - Template for creating new development tasks
- `README.md` - This file, explaining the organization

### `/analysis/`
Strategic analysis and vision documents:
- `core-vision-analysis.md` - Analysis of Secondary Mind's core vision and development paths
- `development-paths-analysis.md` - Comprehensive analysis of potential development directions

### `/features/`
Feature-specific documentation organized by feature name:

#### `/features/smart-context-collection/`
Complete documentation for the Smart Context Collection feature:
- `focused-vision.md` - Refined, focused vision and workflow analysis
- `comprehensive-vision.md` - Detailed comprehensive vision document
- `implementation-plan.md` - Complete implementation roadmap and architecture
- `technical-specs.md` - Detailed technical specifications for Phase 1 implementation

### `/completed-tasks/`
Archive of completed development tasks with implementation notes and lessons learned.

## File Naming Conventions

- Use kebab-case for file names
- Be descriptive but concise
- Group related files in appropriate subdirectories
- Keep important reference files (rules, templates) at root level

## Usage Guidelines

1. **Development Rules**: Always reference `development-rules.md` before starting new work
2. **Feature Documentation**: Create new subdirectories under `/features/` for each major feature
3. **Analysis**: Place strategic analysis and vision documents in `/analysis/`
4. **Task Management**: Use `task-template.md` for new tasks, move completed tasks to `/completed-tasks/`

This organization ensures easy navigation while keeping the most important reference files easily accessible at the root level.
